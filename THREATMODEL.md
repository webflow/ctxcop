# Threat model

This document is for security-conscious users deciding whether to trust
ctxcop with their credentials, and for security researchers deciding what
counts as a vulnerability. It is deliberately explicit about what we
guarantee, what we don't, and where the documented bypasses live.

ctxcop is **defense in depth, not a hermetic seal.** If you don't want a
production credential to enter an AI agent's context window, the safest
move is still to keep that credential out of the developer environment in
the first place. ctxcop reduces the surface area of accidental leakage and
makes intentional leakage visible; it does not make either impossible.

## Trust model

ctxcop trusts:

- The OS process boundary. Each hook invocation is a separate process
  with its own memory and file descriptors.
- The harness's documented hook-execution contract (Claude Code, Codex,
  Cursor JSON shapes for `PreToolUse`/`PostToolUse`/etc.; Pi's
  in-process `ExtensionAPI` typings; OpenCode's `Hooks` plugin API).
  Aider is the exception: no hook contract exists, so ctxcop instead
  trusts the stability of Aider's `.aider.conf.yml` schema keys
  `lint-cmd`, `test-cmd`, and `read:`, plus the semantics that Aider
  invokes wrapped `lint-cmd`/`test-cmd` values via the user's shell
  (so the `ctxcop run --` wrap actually intercepts).
- The integrity of the user's harness configuration files
  (`~/.claude/settings.json`, `~/.codex/config.toml`,
  `~/.cursor/hooks.json`, `~/.pi/agent/extensions/ctxcop.ts`,
  `~/.config/opencode/plugins/ctxcop.ts`,
  `~/.aider.conf.yml`, `~/.aider/ctxcop-priming.md`). If those are
  mutated by another process, ctxcop's hook entries and wrap
  transformations can be removed without ctxcop noticing.
- The Go runtime, the standard library, and the pinned `betterleaks`
  detection library (see `THIRD_PARTY_AUDIT.md` for how we manage that
  trust).

ctxcop does NOT trust:

- **Tool output.** All `tool_response` content is treated as adversarial.
  The scanner runs against the response before any agent sees it.
- **Agent reasoning.** The agent is an untrusted intermediary. ctxcop
  blocks credential-bearing tool inputs the agent generates and warns
  the agent when something credential-shaped appears in its context.
- **MCP server responses.** A compromised MCP server is a separate trust
  boundary; ctxcop redacts in and out, but cannot recover from a server
  that exfiltrates the credential to a third party.
- **Test fixtures in skip-list paths.** Skip-listed credentials are
  assumed synthetic; if someone smuggles a real credential into
  `testdata/`, ctxcop won't redact it.
- **Compaction summaries generated by the model.** The model can
  re-synthesize credential-shaped text from previously-redacted content;
  `PreCompact` and `PostCompact` handlers warn but cannot prevent.

## In-scope threats

ctxcop's hooks are designed to mitigate:

> Aider carve-out: Aider has no hook lifecycle, so items 3–6 below
> don't apply to it as stated. Aider's actual coverage is limited to
> the static `lint-cmd`/`test-cmd` wrap and `read:` priming file — see
> [docs/harnesses.md#aider](docs/harnesses.md#aider) and the Aider
> entries under "Known bypass classes" below.

1. **Credential extraction via tool output.** An agent runs `aws sts
   get-session-token`, the response contains AWS credentials, the agent
   would otherwise see them. ctxcop intercepts and redacts.
2. **Credential leakage via context-window summarization.** Compaction
   compresses prior turns; credential-shaped values in source content can
   inherit into the summary. ctxcop warns at compact time.
3. **User pasting credentials into chat.** The user types or pastes a
   credential into a prompt. ctxcop's `UserPromptSubmit` /
   `BeforeSubmitPrompt` blocks the prompt with a guidance message.
4. **Agent-composed credential exfiltration.** The agent embeds a
   credential it saw earlier into a `WebFetch` URL or an MCP tool input.
   ctxcop's `PreToolUse` blocks the call.
5. **Write-to-disk of credential-shaped values.** The agent tries to
   write a `.env` file with a literal credential. ctxcop's Write/Edit
   handler blocks the write with guidance to use `process.env.X` or
   equivalent.
6. **Read of credential-bearing files.** The agent reads a file
   containing apparent credentials. ctxcop intercepts at `PreToolUse`,
   creates a redacted copy in `$TMPDIR/ctxcop/`, and redirects the read
   to that copy.

## Known bypass classes

Every documented bypass is listed here — they're discoverable from
the source anyway, and consolidating them in one place is more useful
to operators than scattering caveats across handler files.

Each entry includes a current status. Closed bypasses are kept on the
list with the commit that closed them so the history is preserved.

### Open

- **Cursor `WebSearch` and `AskQuestion` tools bypass hooks entirely.**
  Upstream coverage gap, tracked at Cursor forum threads 160761 and
  152230. ctxcop has no signal to act on for these tool dispatches.
  Reference: `internal/harness/cursor/sessionstart.go:22`.

- **Codex `unified_exec`, `local_shell`, and streaming-shell variants
  bypass hooks.** Only the standard `ShellCommandToolCallParams` payload
  shape triggers Codex's PreToolUse. Other shell paths flow through
  unredacted. Reference: `internal/harness/codex/sessionstart.go:18-20`.

- **Cursor built-in tool output bypasses `updated_mcp_tool_output`.**
  Cursor's `updated_mcp_tool_output` field is documented as generic but
  empirically only consumed for MCP-prefixed tools; built-in Read /
  Shell / Write responses flow through unmodified. Cursor's Read is
  pre-empted via the `PreToolUse` redirect (so this affects Shell and
  Write only). Reference: `internal/harness/cursor/sessionstart.go:24`.

- **MCP form-mode elicitation credentials.** The MCP specification
  forbids form-mode elicitations from carrying credentials, but cannot
  enforce that. ctxcop flags violations via systemMessage in
  `ElicitationResult`, but the literal value has already reached the
  MCP server through a non-spec-compliant path by then. Rotate any
  credential surfaced this way. Reference:
  `internal/harness/claudecode/elicitationresult.go`.

- **PreCompact summary preservation.** Compaction summaries can preserve
  credential-shaped text even when the source was redacted, because the
  model can re-synthesize patterns. `PreCompact` and `PostCompact`
  warn but cannot rewrite the summary. References:
  `internal/harness/claudecode/precompact.go`,
  `internal/harness/claudecode/postcompact.go`.

- **Aider: no `UserPromptSubmit` interposition.** Aider has no hook
  lifecycle at all (upstream is in maintenance mode; see
  [Aider-AI/aider#4485](https://github.com/Aider-AI/aider/pull/4485)),
  so a credential pasted into Aider's chat prompt reaches the model's
  context and the transcript on disk unfiltered. The priming file
  guides the model to steer users toward abstract references, but
  this is guidance, not enforcement. Reference:
  `internal/harness/aider/priming.go`.

- **Aider: auto-detected linters bypass the wrap.** When
  `.aider.conf.yml` has no explicit `lint-cmd`, Aider falls back to
  per-language auto-detected linters (`ruff` for Python, etc.) invoked
  directly. Those bypass the `ctxcop run --` wrap that install applies
  to explicit `lint-cmd` entries. Install-time warning surfaces the
  gap. Reference: `internal/harness/aider/install.go` (function
  `preflightWarnings`).

- **Aider: LLM-emitted edit blocks bypass ctxcop.** If the model
  returns an edit block containing a literal secret, Aider's parser
  applies it to the local file directly. There is no
  `PreToolUse`-equivalent fire point. Compensating layers: `ctxcop
  scan` piped through a git pre-commit hook, or CI-side secret
  scanning. Reference: `docs/known-limits.md#aider`.

- **Aider: no LiteLLM callback interposition.** Aider uses LiteLLM
  under the hood, and LiteLLM supports `success_callback` /
  `failure_callback` — but Aider does not expose a userland knob to
  register one. A payload-level chokepoint like Pi's
  `before_provider_request` would need Aider to surface that API.
  Blocked upstream; tracked in `ROADMAP.md`.

- **Multi-line streaming chunk boundaries.** ctxcop's redactor splices
  on completed JSON tool_responses. Streaming variants of tool dispatch
  that deliver output line-by-line can split a credential across two
  emit boundaries — neither half matches the rule. Documented trade-off
  for `ctxcop run --stream`. Reference: `internal/runner/stream.go`.

- **Cursor agent-loop file exploration.** Short user prompts like "read
  test" can trigger Cursor's agent-loop to enumerate and read files
  *without* firing `PreToolUse`. Empirically verified during rc.4
  dogfooding. Reference: `internal/harness/cursor/sessionstart.go:21`.

### Closed

- **ANSI-interleaved secrets.** Detector ran on the ANSI-stripped buffer
  but `Splice` couldn't find the contiguous secret bytes in the
  original, so the redaction silently no-op'd while the audit log
  claimed a redaction. Closed in commit
  [`a149f92`](https://github.com/webflow/ctxcop/commit/a149f92) with
  regression coverage in `internal/redact/ansi_test.go`.

- **Pause silent fail across harnesses.** `ctxcop pause` only short-
  circuited Claude Code's `PreToolUse`; Codex, Cursor, and Claude
  Code's other handlers continued making decisions. Closed in commit
  [`b90aa9f`](https://github.com/webflow/ctxcop/commit/b90aa9f). Pause
  state now surfaces as a SessionStart banner and a per-prompt notice
  ([`1d71c7a`](https://github.com/webflow/ctxcop/commit/1d71c7a)).

- **Cursor skip-list ignored on Read/Write.** Cursor's path-aware
  handlers didn't consult the project skip-list, so intentional fixture
  files got redirected to redacted temp copies. Closed in commit
  [`22be61c`](https://github.com/webflow/ctxcop/commit/22be61c).

- **Claude Code PostToolUse silent passthrough on non-JSON
  tool_response.** Plain-text returns bypassed the scanner. Closed in
  commit [`0e23691`](https://github.com/webflow/ctxcop/commit/0e23691).

## Detection-layer caveats

Regex-based detection has structural failure modes that are inherent to
the approach, not bugs:

- **Low-entropy custom tokens.** A bearer token shaped like
  `dGVzdHRva2VuMTIzNA==` may not exceed the entropy threshold needed
  to distinguish from a Base64-encoded English word. Mitigation: add
  a project-specific rule to your `.ctxcop.toml` with a known prefix
  or service-name discriminator.

- **Novel SaaS credential formats.** A new vendor introduces a
  credential prefix ctxcop's embedded ruleset hasn't seen.
  Mitigation: add the rule (and please open a PR upstreaming it).

- **Adversarially constructed strings.** Credentials deliberately
  shaped to evade the ruleset are not in scope — ctxcop assumes the
  agent and tools are not actively cooperating in exfiltration.

## Out of scope

These are documented non-goals, listed so it's clear what *not* to
report:

- Endpoint compromise. A user with code execution can do anything ctxcop
  can. ctxcop is not a sandbox.
- Malicious user intentionally pasting their own credentials. ctxcop
  blocks the obvious case; a determined user can always bypass.
- Model side-channel inference of credentials from non-credential data
  (e.g., the model guessing a token from a context clue).
- Compromised MCP server. Separate trust boundary; ctxcop's redaction is
  best-effort, and a compromised server can persist the value before
  ctxcop sees it.

## Verification claims that hold

These are guarantees ctxcop's design supports and which testing covers:

- **Cosign verification of release artifacts.** The published binary
  verifies against a cosign signature whose certificate identity is
  pinned to the workflow path at the release tag. See `SECURITY.md`
  for the verify command.

- **Reproducible builds.** A clean rebuild from the source tag produces
  a bit-identical binary (same Go version, same goreleaser version, same
  `SOURCE_DATE_EPOCH`).

- **Audit-log completeness.** Every redaction event ctxcop emits
  (action `redacted` / `blocked` / `warned`) writes one JSONL line to
  the audit log when `$CTXCOP_AUDIT_LOG` is set. No silent drops on
  the happy path.

- **Skip-list consistency across harnesses.** A path matched by the
  skip-list bypasses redaction equivalently on Claude Code, Codex, and
  Cursor. Closed gap in commit `22be61c`; regression covered in
  `internal/skiplist/skiplist_test.go` and per-harness pause/skip tests.

## Reporting threat-model bugs

If you find a bypass class not on the "Open" list above, that's a
vulnerability — please file via the [PSA flow](SECURITY.md#reporting-a-vulnerability)
rather than as a public issue. We'll add it to the "Open" list after
acknowledgment and to the "Closed" list once a fix ships.

If you find a documented bypass and want to discuss mitigations or
work-arounds, a public issue is fine — the bypass is already known.

## Updating this document

Any PR that changes detection coverage or introduces a new bypass class
must update this file. The PR template includes a checkbox for this; the
`internal/redact/**` and `internal/rules/**` paths require
`@webflow/infrastructure-security` review per `CODEOWNERS`.
